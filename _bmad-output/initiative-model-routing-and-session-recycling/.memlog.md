# Decision Log: Task-Type Model Routing & Session Recycling

- **Date:** 2026-11-05
- **Topic:** Model Tiering by Task Type, Concurrency Optimization, and Session Recycling
- **Author:** BMad

## Context
Running high-parameter frontier reasoning models on minor chores exhausts provider rate limits and 5-hour sliding window quotas. Furthermore, running prolonged agent interactions in a single session causes context window bloat (>80k tokens), resulting in attention degradation, looping, and sluggish latency.

## Decisions

1. **Deterministic Local Model Tiering (Zero External API Keys)**
   - *Decision:* Classify task types into `frontier`, `balanced`, and `fast` tiers using local deterministic rules rather than querying third-party decision APIs.
   - *Rationale:* Eliminates dependencies on external keys (like TypeSafe), guarantees sub-millisecond execution, and works offline in any air-gapped environment.

2. **Per-Agent Concrete Model Resolution**
   - *Decision:* Maintain a concrete mapping matrix for each supported agent (`claude`, `agy`, `codex`) mapping tiers to provider models:
     - `frontier`: `claude-3-7-sonnet-latest`, `pro`, `o3-mini`
     - `fast`: `claude-3-5-haiku-latest`, `flash`, `gpt-4o-mini`
   - *Rationale:* Gives developers optimal model performance matching task difficulty, preserving precious reasoning budgets.

3. **Warm-Start Session Recycling Pattern**
   - *Decision:* Implement `sprout session recycle` to snapshot state to `.sprout/handoff.md` and reboot the agent process inside the existing Herdr pane.
   - *Rationale:* Solves "Context Rot" without amnesia. The agent starts fresh with ~3k tokens of clean instructions rather than 100k tokens of stale logs.
